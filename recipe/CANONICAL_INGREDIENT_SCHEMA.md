# Canonical Ingredient System - Firestore Schema

## Collection: `canonical_ingredients`

**Path:** `/canonical_ingredients/{ingredientId}`

**Type:** Top-level collection (global, shared across all users)

**Purpose:** Standardized ingredient catalog to prevent duplicates and ensure consistency across pantry items, recipes, and shopping lists.

---

## Document Structure

### Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | String | Yes | Document ID (auto-generated by Firestore) |
| `name` | String | Yes | Primary normalized name (lowercase, trimmed, accents removed) |
| `synonyms` | Array<String> | No | Alternative names and spellings (normalized) |
| `category` | String | Nullable | Optional category (e.g., "Dairy", "Vegetables") |
| `defaultUnit` | String | Nullable | Suggested unit for this ingredient (e.g., "grams", "pieces") |
| `createdAt` | Timestamp | Yes | Creation timestamp |
| `updatedAt` | Timestamp | Yes | Last update timestamp |

---

## Field Details

### `name` (String, Required)

- **Normalized format:** Lowercase, trimmed, accents removed
- **Examples:**
  - `"tomato"` (not "Tomato" or "tomáto")
  - `"cebolla"` (not "Cebolla" or "cebólla")
  - `"pollo"` (not "Pollo" or "póllo")
- **Purpose:** Primary identifier for matching and searching
- **Uniqueness:** Should be unique (enforced by application logic)

### `synonyms` (Array<String>, Optional)

- **Format:** Array of normalized strings
- **Purpose:** Handle variations and alternative names
- **Examples:**
  - For `name: "tomato"`, synonyms might be: `["tomatoes", "tomate"]`
  - For `name: "onion"`, synonyms might be: `["cebolla", "onions"]`
- **Normalization:** All synonyms are normalized (lowercase, trimmed, accents removed)

### `category` (String, Nullable)

- **Purpose:** Optional categorization for filtering/grouping
- **Examples:** "Dairy", "Vegetables", "Meat & Poultry", "Spices & Condiments"
- **Note:** Can be null if category is not applicable

### `defaultUnit` (String, Nullable)

- **Purpose:** Suggested unit when adding this ingredient to pantry
- **Examples:** "grams", "kilograms", "liters", "pieces", "cups"
- **Note:** Can be null if no default unit is applicable

### `createdAt` (Timestamp, Required)

- **Purpose:** Track when ingredient was added to catalog
- **Format:** Firestore Timestamp

### `updatedAt` (Timestamp, Required)

- **Purpose:** Track last modification time
- **Format:** Firestore Timestamp
- **Auto-updated:** Should be updated whenever the document is modified

## Normalization Rules

### Name Normalization

All ingredient names are normalized using the following rules:

1. **Lowercase:** Convert to lowercase
   - `"Tomato"` → `"tomato"`
   - `"CEBOLLA"` → `"cebolla"`

2. **Trim:** Remove leading/trailing whitespace
   - `"  tomato  "` → `"tomato"`

3. **Whitespace Normalization:** Replace multiple spaces with single space
   - `"tomato   sauce"` → `"tomato sauce"`

4. **Accent Removal:** Remove diacritics (accents)
   - `"tomáto"` → `"tomato"`
   - `"cebólla"` → `"cebolla"`
   - `"pélo"` → `"pelo"`
   - `"ñ"` → `"n"` (special case: ñ becomes n)

### Supported Accent Mappings

|----------|------|----------|------|
| á, à, ä, â, ã, å | a | Á, À, Ä, Â, Ã, Å | a |

## Security Rules

### Recommended Firestore Security Rules

```javascript
match /canonical_ingredients/{ingredientId} {
  // Allow read for all authenticated users
  allow read: if request.auth != null;
  
  // Allow create/update for authenticated users (can be restricted to admins)
  allow create: if request.auth != null 
    && request.resource.data.keys().hasAll(['name', 'createdAt', 'updatedAt'])
    && request.resource.data.name is string
    && request.resource.data.name.size() > 0;
  
  allow update: if request.auth != null
    && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['synonyms', 'category', 'defaultUnit', 'updatedAt']);
  
  // Prevent deletion (or restrict to admins)
  allow delete: if false; // or: if request.auth.token.role == 'admin';
}
```

## Critical Rules

### Rule 1: Availability Consistency

**"An ingredient marked as available must NEVER appear as missing elsewhere"**

This means:
- If a `PantryItem` has `canonicalIngredientId = "abc123"` and `quantity > 0`, then:
  - Any `RecipeIngredient` with `canonicalIngredientId = "abc123"` should NOT appear in shopping lists
  - The matching logic must check canonical IDs, not just names

### Rule 2: Name Matching

- When matching ingredients, always check `canonicalIngredientId` first
- If `canonicalIngredientId` is null, fall back to name-based matching
- Name matching uses normalized names (lowercase, trimmed, accents removed)

### Rule 3: Synonym Handling

- Synonyms are normalized and stored in the `synonyms` array
- When searching, check both `name` and `synonyms`
- Example: Searching for "tomatoes" should match canonical ingredient with `name: "tomato"` if "tomatoes" is in synonyms

## Query Patterns

### Find by Name

```dart
// Exact match on normalized name
final query = firestore
  .collection('canonical_ingredients')
  .where('name', isEqualTo: CanonicalIngredient.normalize(ingredientName))
  .limit(1);
```

### Find by Synonym (requires in-memory filtering)

```dart
// Firestore doesn't support array-contains with normalization
// Fetch all and filter in memory
final allIngredients = await firestore
  .collection('canonical_ingredients')
  .get();
  
final matching = allIngredients.docs
  .map((doc) => CanonicalIngredient.fromFirestore(doc))
  .where((ing) => ing.matches(ingredientName))
  .firstOrNull;
```

### Get All Ingredients (sorted)

```dart
final query = firestore
  .collection('canonical_ingredients')
  .orderBy('name')
  .get();
```
